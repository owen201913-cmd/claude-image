# 乾淨 Windows 驗收的下一步

紀錄日期：2026-10-12。這是本機驗收準備，不是已通過的安裝測試。

## 已有證據

- 同一個專案專用 80 GiB VHDX 已套用官方 Windows 11 Enterprise 評估映像，已卸載；沒有建立第二個測試映像。
- RC11、RC12 與原操作單已放入映像的 `C:\ClaudeImageQA`，保存後的檔案大小及 SHA-256 相符。
- 離線測試記錄頁與返回指引也已放入同一資料夾，兩份原檔讀回核對通過；本次掛載路徑已移除、映像已卸載。初次啟動失敗及修正後的實際成功分開保存在 [複製記錄](native-guest-evidence-copy-20261012.json)。
- 原系統的預設開機項目是 `Windows 11`，等待時間 30 秒。開機設定的唯讀快照及現有 Microsoft EFI 程式資訊已保存。
- 批准後的初次執行已建立唯一測試項目並設定七個欄位，但 Windows 讀回補上的兩個定位後綴使原檢查拒絕。已以經獨立審查的新續接程式完成同一項目的加入選單；讀回確認原 Windows 11 仍為預設、等待 30 秒，其他受檢查的原設定保持一致。原失敗記錄保留，沒有重新建立項目、重設七個欄位或重啟。詳見 [本次結果](native-phaseb-result-20261012.json)。

## 已批准的具體變更

在開機選單最後新增一個 `Claude Image Clean Windows QA` 項目，只指向上述專案專用 VHDX。原 `Windows 11` 繼續作為預設，30 秒等待時間保持原值。不更換 EFI 程式，不關閉其他專案，也不在這一步重啟。

本次已先保存本機 BCD 備份，檢查當下原設定，建立唯一的專案項目，最後續接完成加入選單。結果不明時停止，不換識別碼重新建立。初版撤回程式也會因這次的定位後綴而拒絕讀回，因此不能直接使用。

只移除本專案項目的修正版撤回工具已完成原始碼審查、獨立審查與 8 個新純資料案例、3 個語法檢查及結果分類／紀錄順序檢查。這是準備完成的證據；執行批准閘門仍關閉，沒有執行刪除，測試開機項目仍保留。需要撤回時，須重新核對同一項目及原系統設定後才執行；不以整份舊備份覆蓋後來的系統設定。若實際開機後欄位或受檢設定改變，工具會停止，先審查差異，不放寬檢查直接移除。

這項變更超出先前「只準備離線映像、不改開機選單」的批准範圍，已另行取得「允許新增，暫不重啟」的批准並完成。它不是免風險或交易級修改；新增選單階段沒有重啟。之後使用者另行確認「已保存工作，允許正常重啟」，新批准與重啟交接另記於 [native-reboot-handoff-20261012.json](native-reboot-handoff-20261012.json)，不改寫原先禁止重啟的紀錄。

## 實際開機仍是另一階段

新增項目成功不等於 Windows 已開機，也不等於 P4 通過。正常重啟已另外批准並執行，命令回傳 0，之後的原系統開機時間已更新。目前觀察到的是 Windows 11 家用版；尚未知道是未選到測試項目，還是測試項目啟動失敗，不能推定測試系統曾成功開機。這次結果另存於重啟交接記錄，不盲目再次重啟。現有 Codex 不會自動出現在新 Windows 裡。

使用者回覆不確定且沒有看到開機選單。一次性指定下一次開機進入既有 QA 項目的工具已準備完成，原始碼及獨立審查通過，新 8 個純資料案例與 3 個語法檢查通過；尚未取得這項新設定與再次重啟的批准，沒有執行。它不修改原預設 Windows 11，拒絕覆寫任何既有一次性開機安排；結果不明時停止。這是新的準備證據，見 [native-once-boot-plan-20261012.json](native-once-boot-plan-20261012.json)，不能視為實際開機或 P4 通過。

新 Windows 首次設定、Claude 安裝與本人登入後，依操作單用本機 TEST 模式建立新的測試任務，驗證普通聊天、圖片與原圖下載、重啟、RC11→RC12 更新、移除與重裝；不使用舊任務、不呼叫 Ngini。每一項以實際結果填入離線記錄頁，另保存原圖及 JSON 證據。返回方式見 [native-boot-return.md](native-boot-return.md)。

## 圖片回覆的目前範圍

RC12 擴充套件本身仍不能保證 Claude 不附加文字。追加狹義帳號 Instructions 後，一次完整的既有圖片重開得到一張卡片且沒有附加正文，來源詢問、一般問答及不存在任務的控制案例也正常。這是有條件的實測樣本；Instructions 為另外啟用的帳號設定，不會由 MCPB 自動修改，也不是所有版本的保證。

乾淨 Windows 安裝及生命週期驗收目前維持 `NOT_RUN_NOT_WAIVED`。尚未正式發布，也沒有新增生圖。
